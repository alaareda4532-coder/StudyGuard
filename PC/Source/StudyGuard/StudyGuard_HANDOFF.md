# StudyGuard --- ملف تسليم المشروع إلى Codex

> اقرأ الملف كاملًا قبل تعديل المشروع. هذا المستند يجمع المتطلبات والسياق
> المعروف؛ الملفات الموجودة فعليًا على القرص هي المرجع النهائي لحالة
> التنفيذ.

## 1. ملخص المشروع

**StudyGuard** تطبيق سطح مكتب لنظام Windows ينظم الدراسة والإنتاجية،
ويطبّق وضع الاستخدام المحدد في الجدول على التطبيقات والمواقع. لكل نشاط
قوائم سماح مستقلة؛ يرسل تنبيهًا قبل النشاط بعشر دقائق، ويفتح التطبيقات
المسموحة ويغلق غير المسموحة عند بدء النشاط بعد تفعيل التحكم صراحةً.

-   **النوع:** Windows Desktop Application
-   **التقنية:** WPF (Windows Presentation Foundation)
-   **اللغة:** C#
-   **إطار العمل:** .NET 10، المتوقع أن يكون Target Framework هو
    `net10.0-windows`
-   **البيئة:** Windows x64، VS Code، CMD
-   **مسار مشروع الكمبيوتر:** `E:\\StudyGuard\\PC\\Source\\StudyGuard`
-   **مجلد تشغيل الكمبيوتر وبنائه:** `E:\\StudyGuard\\PC\\StudyGuardApp`
-   **مجلد النسخ الاحتياطية:** `E:\\StudyGuard\\PC\\Backups`
-   **اللغة واتجاه الواجهة:** العربية، RTL
-   **التصميم المطلوب:** ثيم داكن حديث، وشريط تنقل جانبي على اليمين.
-   **مستوى صاحب المشروع:** مبتدئ؛ اشرح الخطوات بالمصري وبوضوح، ولا
    تفترض أنه نفّذ أمرًا لم يؤكد تنفيذه.

> هذا التسليم يخص نسخة Windows فقط. حزمة الإرسال الجاهزة موجودة في
> `E:\StudyGuard\PC\Distribution\StudyGuard-Windows-x64`.

## 2. تعليمات إلزامية إلى Codex

1.  افحص الملفات الحالية قبل أي تعديل، ولا تنشئ مشروعًا جديدًا فوق المشروع
    الموجود.
2.  لا تستخدم `dotnet new ... --force`، ولا تستبدل الملفات كاملة لمجرد
    السهولة.
3.  أنشئ نسخة احتياطية قبل التغييرات الكبيرة داخل
    `E:\\StudyGuard\\Backups`.
4.  ميّز بين ما هو منفذ فعليًا وما هو مجرد صفحة أو خطة مستقبلية.
5.  لا تدّعِ نجاح البناء قبل تشغيله والتحقق من النتيجة.
6.  بعد كل مرحلة، ابنِ المشروع واختبر التغيير قبل الانتقال لغيره.
7.  عندما يلزم استبدال ملف، أعطِ المستخدم الملف كاملًا مع المسار الدقيق
    ووضّح أن الاستبدال كامل.
8.  لا تغيّر التصميم أو المعمارية أو أسماء العناصر بلا داعٍ.
9.  لا تضف مكتبات خارجية أو قاعدة بيانات إلا لسبب واضح.
10. لا تنفّذ قيودًا حقيقية على Windows، أو تغيّر الحسابات والصلاحيات، أو
    تنشئ خدمة تعمل بالخلفية دون تخطيط وموافقة صريحة واختبارات آمنة. حافظ
    على آلية إيقاف واستعادة واضحة.
11. لا تفترض وجود Git أو اختبارات أو SQLite قبل فحص المشروع.
12. لا تحذف ملفات غريبة قبل التحقق من محتواها والغرض منها.

## 4. الصفحات المطلوبة

1.  **الرئيسية (Home):** ملخص مفيد عن اليوم والجدول.
2.  **الجدول (Schedule):** عرض أنشطة الأسبوع وإضافتها وتعديلها وحذفها.
3.  **الاستثناءات (Exceptions):** قائمة عامة للتطبيقات والمواقع التي
    تبقى مسموحة في جميع الأوضاع، بالإضافة إلى القوائم الخاصة بالنشاط.
    التطبيقات المستثناة لا تُشغّل تلقائيًا؛ يتم تجاهلها عند إغلاق
    التطبيقات غير المسموحة.
4.  **إعدادات الصلاة (Prayer Settings):** اختيار مدينة مصرية، والصلوات
    المفعلة، ومدة السكون القسري بعد الأذان.
5.  **الأحداث (Events):** صفحة مستقبلية للأحداث والتذكيرات.
6.  **الإعدادات (Settings):** إعدادات التطبيق.

وجود صفحة أو زر لا يعني أن وظيفته مكتملة. افحص التنفيذ الحقيقي قبل وصفه
للمستخدم بأنه يعمل.

## 5. الجدول الأسبوعي --- ما ظهر في الكود السابق

كان الكود الخلفي يستخدم قائمة من `ScheduleEntry`، مع تخزين محلي في JSON.
خصائص العنصر:

-   `DayName`: اسم اليوم للعرض.
-   `DayTag`: معرّف اليوم للفلترة.
-   `ActivityName`: اسم النشاط.
-   `StartTime` و`EndTime`: وقتا البداية والنهاية من نوع `TimeOnly`.
-   `DisplayText`: نص النشاط المعروض في القائمة.
-   `Id`: معرّف ثابت للنشاط.
-   `AllowedApplications`: قائمة قديمة محفوظة للتوافق؛ لم تعد تستخدمها
    الواجهة أو آلية الحجب.
-   `BlockApplications` و`BlockWebsites`: تفعيل نوع الحجب لكل فترة مجدولة.
-   `BlockedApplications`: مسارات التطبيقات التي يجب إنهاؤها أثناء هذا
    النشاط؛ لا يتأثر أي تطبيق غير موجود بهذه القائمة.
-   `BlockedWebsites`: أسماء نطاقات المواقع التي تُحجب أثناء هذا النشاط.
-   `AllowedWebsites`: قائمة السماح القديمة محفوظة للتوافق ولا تطبق.

مسار البيانات يُنشأ تحت:

`%LOCALAPPDATA%\\StudyGuard\\schedule.json`

لا توجد معلومات تؤكد استخدام SQLite؛ التخزين المعروف في الكود السابق هو
JSON.

### الأنشطة الافتراضية التي ظهرت

كان الكود ينشئ هذه الأنشطة لكل يوم من أيام الأسبوع:

  النشاط                            البداية   النهاية
  ------------------------------- --------- ---------
  نوم                                 22:00     06:00
  تحضيرات وصلاة                       06:00     07:00
  مذاكرة                              07:00     13:00
  صلاة الظهر أو قراءة                 13:00     14:00
  سماع محاضرات أو تعلّم شيء جديد       14:00     16:00
  صلاة أو قراءة                       16:00     17:00
  برمجة                               17:00     19:00
  أكل                                 19:00     20:00
  جلوس مع العائلة                     20:00     22:00

لا تكتب فوق بيانات المستخدم الحالية بهذه القيم إذا كان قد عدّل الجدول
وحفظه.

### وظائف كانت موجودة في الكود الذي شاركه المستخدم

-   تحميل الجدول من JSON إذا كان الملف موجودًا.
-   إنشاء الجدول الافتراضي وحفظه إذا لم يوجد الملف.
-   حفظ التغييرات في JSON.
-   اختيار اليوم من `ScheduleDayComboBox`.
-   عرض أنشطة اليوم في `ScheduleListBox`.
-   ترتيب الأنشطة عند العرض، مع معاملة خاصة لنشاط النوم الذي يبدأ الساعة
    22:00.
-   عرض بيانات النشاط المختار في حقول التحرير.
-   تعديل اسم النشاط ووقتي البداية والنهاية.
-   إضافة نشاط من نافذة مستقلة تطلب الاسم والمواعيد، وتتيح اختيار يوم أو
    أكثر. تُنشأ نسخة مستقلة بنفس الاسم والمواعيد في كل يوم محدد، واليوم
    المعروض محدد افتراضيًا.
-   حذف النشاط بعد تأكيد المستخدم.
-   التحقق من أن الاسم غير فارغ، والوقت بصيغة `HH:mm`، وأن البداية لا
    تساوي النهاية.
-   إظهار رسائل حالة أو تحذير.

هذه قائمة مستندة إلى الكود السابق، وليست ضمانًا بأن جميع الوظائف تعمل في
النسخة الحالية. اختبرها.

### نقاط يجب التحقق منها

**الأنشطة التي تعبر منتصف الليل:** نشاط النوم الافتراضي من 22:00 إلى
06:00. تحقق هل منطق التحقق يدعم انتهاء النشاط في اليوم التالي أم لا. لا
تغيّر هذا السلوك بصمت.

**إضافة لعدة أيام:** نافذة الإضافة تنسخ النشاط ومواعيده إلى كل الأيام
المحددة. بعد الإنشاء، كل نسخة مستقلة ويمكن تعديلها أو حذفها منفردة.

## 6. خطأ البناء الأخير

ظهر خطأ شبيه بالتالي:

`MainWindow.xaml(4,15): error MC3000: 'x' is an undeclared prefix. Line 4, position 15.`

وظهر سابقًا خطأ عن وسم `StackPanel` غير مغلق أو غير متطابق. من
الاحتمالات:

-   لصق جزء من XAML بدل الملف الكامل.
-   غياب تعريف مساحة الأسماء `xmlns:x`.
-   وجود وسوم غير متوازنة أو أجزاء مكررة.
-   تكرار جزء من `ScrollViewer` أو وضعه خارج النافذة الجذرية.

هذه احتمالات وليست تشخيصًا نهائيًا. اقرأ الملف كاملًا قبل الإصلاح.

الهيكل الأساسي المتوقع لملف WPF:

``` xml
<Window
    x:Class="StudyGuard.MainWindow"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    Title="StudyGuard">
    <!-- محتوى النافذة -->
</Window>
```

هذا مثال توضيحي للبنية، وليس بديلًا عن ملف الواجهة الفعلي.

## 7. الملفات الأساسية

-   **`StudyGuard.csproj`:** إعدادات المشروع وإطار العمل وخصائص البناء.
    تحقق من إعدادات WPF و`net10.0-windows`.
-   **`App.xaml` و`App.xaml.cs` إن وُجد:** نقطة بدء التطبيق والموارد
    العامة.
-   **`MainWindow.xaml`:** واجهة النافذة، الصفحات، عناصر التحكم، أسماء
    العناصر وربط الأحداث.
-   **`MainWindow.xaml.cs`:** منطق الواجهة، التنقل، ومعالجة الجدول
    والملف المحلي.
-   **`SystemWebsiteProxy.cs`:** وكيل HTTP محلي لقائمة المواقع، مع حفظ
    إعداد وكيل Windows السابق واستعادته.
-   `RestrictionNoticeWindow.xaml` ملف قديم لم يعد يُستخدم؛ أزيلت نافذة
    محاولة فتح تطبيق أو موقع محظور بناءً على طلب المستخدم.
-   **`%LOCALAPPDATA%\\StudyGuard\\schedule.json`:** ملف بيانات الجدول
    الذي ينشئه التطبيق.
-   **`%LOCALAPPDATA%\\StudyGuard\\settings.json`:** إعدادات تفعيل
    التحكم في التطبيقات والمواقع.
-   **`bin` و`obj`:** مخرجات بناء واستعادة؛ لا تعدّلها يدويًا عادةً.

-   لا تجعل الواجهة تدّعي أن ميزات مستقبلية تعمل.

## 9. حالة ميزات التحكم

التنفيذ الحالي يضيف هذه الآليات، لكن لم تُجرَ بعد اختبارات تشغيل يدوية
على جهاز المستخدم؛ نجاح البناء وحده لا يثبت عملها وقت التشغيل:

-   قوائم تطبيقات ومواقع لكل نشاط، محفوظة داخل `schedule.json`.
-   لكل نشاط وضع اختياري لحجب كل التطبيقات عدا قائمة تطبيقات مسموحة،
    ووضع مستقل لحجب كل المواقع عدا قائمة نطاقات مسموحة. يعمل كل وضع
    أثناء النشاط المجدول فقط. عند تفعيله تتوقف آلية حجب العناصر المحددة
    للفئة نفسها، وتظل الاستثناءات العامة مسموحة. بيانات القائمتين تحفظ
    مع النشاط في `schedule.json`.
-   صفحة الجدول تتيح حذف كل فترات الأسبوع بعد تأكيد صريح. الجدول الفارغ
    يبقى فارغًا بعد إعادة تشغيل التطبيق ولا يعاد ملؤه تلقائيًا بالجدول
    الافتراضي.
-   نطاق الحجب الافتراضي في صفحة الجدول هو الفترة نفسها طوال الأسبوع؛
    يستطيع المستخدم تغييره إلى اليوم المحدد فقط.
-   صفحة إعدادات الصلاة تتيح اختيار مدينة من قائمة مدن مصرية، الصلوات
    الخمس، ومدة السكون. بعد التفعيل يظهر تنبيه عند موعد الصلاة ثم يطلب
    Windows السكون القسري؛ إذا أُوقظ الجهاز أثناء مدة السكون يعيد التطبيق
    طلب السكون حتى تنتهي المدة. الميزة مطفأة افتراضيًا وتحتاج بقاء
    StudyGuard يعمل بالخلفية. مواقيت اليوم تُجلب من AlAdhan باستخدام
    طريقة الهيئة المصرية العامة للمساحة (method 5)، وتُحفظ محليًا في
    `settings.json`. إذا لم يتوفر الإنترنت ولا توجد مواقيت محفوظة لليوم،
    لا يستطيع التطبيق تنفيذ تنبيه الصلاة لذلك اليوم. المدينة الافتراضية
    هي بني سويف، ومدة السكون الافتراضية 10 دقائق مع إمكان تغييرها. صفحة
    إعدادات الصلاة داكنة، والقوائم المنسدلة بخلفية بيضاء ونص أسود بناءً
    على طلب المستخدم.
-   صفحة الاستثناءات العامة تحفظ مسارات التطبيقات ونطاقات المواقع في
    `settings.json`. تُضم الاستثناءات إلى سماح النشاط الحالي؛ التطبيقات
    لا تُشغّل تلقائيًا من قائمة الاستثناءات.
-   الصفحة الرئيسية تعرض النشاط الجاري وفترته والوقت المتبقي وملخص
    سياسات المنع، وتعرض صورة العلامة التجارية المضمّنة في المشروع.
-   صفحة الجدول الأسبوعي تتيح تفعيل حجب التطبيقات أو المواقع لكل فترة،
    وتحديد نطاق التغيير: اليوم المختار أو كل الفترات ذات وقت البداية
    والنهاية نفسيهما عبر الأسبوع. قوائم التطبيقات والمواقع المحظورة
    تتبع النطاق المختار؛ بقية التطبيقات والمواقع تظل متاحة ما لم تظهر
    في الاستثناءات العامة.
-   عند رصد تطبيق موجود في `BlockedApplications`، يحاول StudyGuard إنهاء
    العملية وشجرتها فور اكتشافها؛ يجري فحص التطبيقات كل ثانية. لا يظهر
    تنبيه ولا يتأثر التطبيق غير المحدد. قد تفقد التغييرات غير المحفوظة،
    وقد يمنع Windows التحكم في عمليات تعمل كمسؤول.
    المواقع المحجوبة تُرفض في الوكيل المحلي من دون نافذة تنبيه عند رصد الطلب.
-   خيار اختياري، مطفأ افتراضيًا، يطلب من Windows إيقاف التشغيل عند
    بداية نشاط اسمه «نوم» (أو `sleep`). يسجل قيمة خاصة به في مفتاح Run
    لحساب Windows الحالي؛ بعد كل تسجيل دخول أثناء نشاط النوم يبدأ مهلة
    10 دقائق ثم يطلب الإيقاف مجددًا بفواصل عشر دقائق إذا ظل الجهاز مفتوحًا.
    يحذف قيمة بدء التشغيل عند انتهاء نشاط النوم أو تعطيل الخيار. لا يُنشئ
    خدمة Windows. يستخدم أمر الإيقاف خيار الإنهاء القسري، لذلك قد تضيع
    البيانات غير المحفوظة عند تفعيل الميزة.
-   تنبيه قبل النشاط بعشر دقائق، داخل النافذة ومن خلال أيقونة منطقة
    الإشعارات عند إخفاء النافذة.
-   التحكم في التطبيقات اختياري. عند تفعيل المفتاح العام وخيار الفترة،
    يبدأ التطبيقات المسموحة لذلك اليوم وينهي التطبيقات المحددة صراحةً في
    قائمة الحظر فقط. تُستثنى التطبيقات الموجودة في الاستثناءات العامة
    وعمليات واجهة Windows الأساسية.
-   حجب المواقع اختياري. لا تُطبّق قائمة الحظر إلا إذا فُعّل خيار حجب
    المواقع في الفترة. النطاقات المضافة لقائمة الفترة تُحجب، وتستثنيها
    قائمة الاستثناءات العامة. بقية النطاقات تظل متاحة. خارج فترات الحجب
    يُستعاد وكيل Windows.
-   صفحة «الحجب الدائم» تحفظ نطاقات مواقع مستقلة عن الجدول، وتطبقها في
    كل الأوقات. لها أولوية على استثناءات المواقع. لا يمكن إزالة النطاق
    قبل مرور 15 يومًا من إضافته، ولا يوجد مفتاح لتعطيل هذه القائمة.
-   لا توجد صفحة تنزيل داخل StudyGuard ولا يشغّل التطبيق yt-dlp. يسمح
    وكيل المواقع باتصالات `yt-dlp.exe` من المسارين المعروفين للمستخدم
    (`%USERPROFILE%\yt-dlp.exe` و`E:\youtube downloader\yt-dlp.exe`)
    إلى نطاقات YouTube وGooglevideo فقط؛ تبقى سياسة الحجب مطبقة على
    اتصالات المتصفحات والبرامج الأخرى. يُدخل المستخدم الأمر بنفسه في CMD.
-   يمنع Mutex لكل حساب Windows تشغيل أكثر من نسخة StudyGuard في الوقت
    نفسه. تشغيله مرة أخرى يرسل طلبًا للنسخة الحالية لإظهار نافذتها بدل
    عرض رسالة «مفتوح بالفعل» أو إنشاء نافذة ثانية. إذا كانت النسخة
    الموجودة قديمة ولا تستجيب لقناة التنشيط، تظهر رسالة توضح إنهاءها من
    منطقة الإشعارات.
-   لا تظهر نافذة منبثقة عند إنهاء تطبيق محظور أو عند رصد محاولة لموقع
    محظور. يبقى إجراء الحجب كما هو، وتبقى تنبيهات الجدول والصلاة.
-   ينشئ StudyGuard اختصارًا تلقائيًا في مجلد Startup لحساب المستخدم،
    لضمان تشغيله عند تسجيل الدخول وتطبيق الحجب الدائم والجدول. تعرض
    صفحة الإعدادات حالة بدء التشغيل ولا توفر مفتاحًا لتعطيله. هذا الجهاز
    مسجل حاليًا لبدء `E:\StudyGuard\PC\StudyGuardApp\StudyGuard.exe`.
-   زر الإغلاق (×) يخفي النافذة من شريط المهام ويبقي StudyGuard في منطقة
    الإشعارات؛ تشغيله مرة أخرى أو النقر على أيقونته يعيد النافذة نفسها.
    الإنهاء النهائي يتم من قائمة أيقونة منطقة الإشعارات. يبدأ التطبيق
    تلقائيًا عند تسجيل الدخول؛ خيار حراسة النوم يستخدم قيمة Run مستقلة
    عن اختصار بدء التشغيل العام. تحتوي القائمة أيضًا على «إعادة تشغيل
    StudyGuard لتطبيق التحديثات»؛ يستعيد الخيار إعداد الإنترنت، يغلق
    النسخة الحالية، ثم يشغل الملف نفسه بعد تحرير Mutex حتى مع وجود حجب
    دائم. الإنهاء العادي يبقى ممنوعًا عند وجود الحجب الدائم.
-   حجب المواقع اختياري، ويستخدم وكيل HTTP محليًا وإعداد وكيل الإنترنت
    لحساب Windows الحالي. يحفظ القيم السابقة في
    `%LOCALAPPDATA%\\StudyGuard\\internet-proxy-backup.json` ويحاول
    استعادتها عند الإيقاف أو الخروج أو تسجيل الخروج، ويعيد المحاولة عند
    التشغيل التالي. يعيد تطبيق الإعداد إذا غيّره تطبيق آخر أثناء عمل
    الحجب، ويرسل إشعار تغيير إعداد Windows للمتصفحات المفتوحة. المتصفحات
    ذات الوكيل المخصص قد تتجاوز الإعداد.
-   استعادة إعداد الإنترنت متاحة من صفحة الإعدادات.
-   عند تعذر قراءة `schedule.json`، يعرض التطبيق جدولًا مؤقتًا، ويحفظ
    نسخة بامتداد `.corrupt-*.json` قبل أول حفظ يستبدل الملف التالف.

تحتاج هذه النقاط إلى اختبار يدوي آمن قبل وصفها بأنها موثوقة، خصوصًا
إغلاق التطبيقات القسري، وتعامل المتصفحات مع الوكيل، واستعادة إعداد
الإنترنت بعد إغلاق التطبيق أو إعادة تشغيل Windows.

لا تزال هذه الميزات غير منفذة أو غير مؤكدة:

-   خدمة Windows مستقلة تعمل عند خروج المستخدم.
-   منع المواقع في المتصفحات التي تتجاوز وكيل Windows أو تستخدم إعدادًا
    مخصصًا.
-   إدارة أحداث وتذكيرات عامة غير تنبيهات الجدول.
-   SQLite أو قاعدة بيانات أخرى.
-   المزامنة عبر الإنترنت أو حسابات المستخدمين.
-   نسخ احتياطي واستعادة من داخل التطبيق.
-   إحصائيات فعلية.
-   تغيير صلاحيات Windows أو إعدادات Windows على مستوى النظام.
-   تغطية اختبارية آلية كاملة لكل ميزات التطبيق؛ توجد اختبارات لوكيل
    المواقع واستثناء yt-dlp، وما زال اختبار التنزيل الفعلي مطلوبًا.
-   مثبت رسمي.
-   تسجيل أخطاء منظم.
-   اكتمال وظائف جميع الصفحات.

لا تصف أيًا منها كميزة منجزة قبل العثور على تنفيذها واختباره.

## 11. أوامر البناء والتشغيل

من CMD:

``` bat
cd /d E:\\StudyGuard
```

البناء:

``` bat
dotnet build
```

أو حدد مشروع الكمبيوتر صراحةً:

``` bat
dotnet build PC\\Source\\StudyGuard\\StudyGuard.csproj -c Release
```

البناء إلى مجلد منفصل، إذا ظل هذا هو الإعداد المتفق عليه:

``` bat
dotnet build
```

التشغيل:

``` bat
dotnet run
```

عند فشل البناء، ابدأ بأول خطأ فعلي؛ قد تكون الأخطاء التالية ناتجة عنه.
لا تنشئ مشروعًا جديدًا لمجرد ظهور خطأ.
